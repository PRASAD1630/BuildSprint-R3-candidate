# WorkMate AI — Design Note

## Goal
Build a daily workplace assistant that prepares client meeting briefs, answers natural-language questions with record-level citations, learns from feedback, and protects private information.

## Architecture
The command-line interface delegates to a Python engine backed by SQLite. Ingestion reads only the requested day and applies feedback from the previous day. Retrieval is constrained by the caller's organization and record visibility before any reasoning occurs. Meeting events are localized using each attendee's IANA time zone. Q&A uses time-bounded records and current task state. Every citation is checked against the set of visible, ingested record IDs.

## Memory
The local database stores source records, feedback, preferences, corrections, ignored topics, forget requests, and audit events. Preferences and forget requests are scoped to one person. Forget filters are applied before retrieval, so forgotten information cannot shape future outputs for that person.

## LLM strategy
The current implementation is primarily deterministic. SQLite is the source of truth for records and access metadata; local FAISS provides semantic nearest-neighbor candidates using normalized MiniLM embeddings generated by FastEmbed/ONNX Runtime. The persisted FAISS ID map is matched to SQLite vector metadata and the current source payload before use. The engine creates an allowlist only after organization/person permissions, timestamp cutoffs, expiry, and forget filtering, then applies those checks again to FAISS hits. Private and restricted records are not indexed. SQLite suppressions make person-scoped forget/correction rules survive index rebuilds. If the vector backend fails, the engine falls back to SQLite retrieval.

The optional provider adapter supports OpenAI, Gemini, and Ollama and is used only for selected client-update questions; it receives a bounded, already permission-filtered evidence set. Retrieved content is untrusted and cannot alter access decisions. Model citations are accepted only when they match retrieved source IDs. The broader model-assisted correction and seven-day conversation-memory features described as future work are not yet complete.

## Evaluation
The supplied `tools/run_days.py` and `tools/score.py` remain unchanged. The visible Days 1–5 are regression fixtures only; no Days 6–15 are present in this workspace. A submission candidate must be replayed through the official harness, with failures categorized by brief recall, task resolution, correction handling, privacy, forgotten facts, expiry, and cost. Never hardcode answer keys or inspect future-day records.

The SQLite schema currently has no multi-session conversation store. The CLI contract has no conversation identifier, so seven-day conversation memory remains future work rather than being mixed into durable workplace facts.
